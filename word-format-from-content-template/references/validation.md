# 比较工具与验收边界

运行 scripts/compare_text.py 或解释比较报告时读取本页。它辅助核对内容，不排版、不转换 DOC、不刷新 Word 字段，也不替代逐页视觉检查。

## CLI

先确定目标环境可用的 Python 解释器，再使用脚本绝对路径或以技能目录为工作目录。下列 `<python>` 表示已发现的解释器；示例文件名需替换为本次真实文件，不直接把占位命令当作已运行结果。

    <python> scripts/compare_text.py source.docx final.docx --scope all --show-diff --report comparison.json
    <python> scripts/compare_text.py source.txt final.txt --show-diff
    <python> scripts/compare_text.py source.md final.md --show-diff

支持 TXT/Markdown 文本比较以及直接 DOCX 比较；旧 .doc 需先使用可用转换器转换并核对转换结果。Markdown 按文本比较，不把排版渲染相同当作原文相同。文本文件采用 UTF-8（可含 BOM）。

| 参数 | 用途与限制 |
| --- | --- |
| --scope all | 默认范围，优先用于交付前核对。实际提取的部件、对象及未覆盖范围以报告为准；“all”不表示理解所有 Word 功能。 |
| --scope content | 对内容范围做聚焦诊断；报告中确认具体排除了哪些部件。不能用于掩盖页眉页脚或模板固定内容的未解释差异。 |
| --show-diff | 显示提取内容的差异，逐项判断是原文改动、派生内容、模板固定文字还是提取局限。 |
| --loose | 忽略空白的辅助诊断。空白可能影响英文、代码或公式含义；即使匹配也返回 REVIEW，不能作为交付通过条件。 |
| --report comparison.json | 将结构化报告写入指定 JSON 路径，用于保留范围、差异、警告及复核线索；不要仅凭文件存在判断成功。 |

报告路径不能指向任一输入，也不能是输入的符号链接或硬链接别名；脚本会拒绝写入并返回 ERROR。终端编码无法表示的字符以转义形式输出，UTF-8 JSON 报告保留原字符；不要把终端转义误当作原文被修改。

## 退出码与表述

| 退出码 | 含义 | 下一步 |
| --- | --- | --- |
| 0 | 指定范围提取结果一致，未触发该工具的复核条件。 | 仍核对规则、对象语义与最终页面；只按实际范围描述一致。 |
| 1 | 检测到差异。 | 审查差异，修复意外变更；有依据的派生内容或模板差异单独说明。 |
| 2 | 输入、解析或运行错误。 | 报告比较未完成，解决具体错误或采用可靠替代，不当作内容不同。 |
| 3 | 需复核，例如使用 --loose 或遇到工具不能充分验证的结构。 | 读取警告并人工/结构核对；不能改参数压成“通过”。 |

有差异和复核警告并存时，两者均需处理；不能只读退出码忽略报告。无法可靠提取的对象保持待复核，不把空提取结果等同空内容。

## DOCX 比较的实际边界

- 比较报告中的提取文字、对象线索或计数只覆盖脚本能识别的范围。图片表达含义、公式语义、自动编号的最终编号、字段显示结果、浮动对象布局等仍须核对。
- 自动编号、字段、复杂或未支持对象即使没有可见文字差异，也可能需要人工检查；对象数量相同不能证明对象内容、位置和关系相同。
- 先用完整范围审查，再根据问题做聚焦比较。用户保护内容、固定模板声明、生成目录/页码分别记录，避免新封面、目录结果等合理差异淹没正文变化。
- 补中性题注/必要图表正文引用句、公式机械独立展示与新增编号、调整四级标题前缀或同步图表引用号会产生真实文字或表示差异，按 [默认预设](default-format.md) 逐项记录授权范围并核对。分别检查新增句是否有图表可见内容依据、公式表达/数值是否保留，以及编号体系含章号时章号是否来自实际结构；脚本返回差异并不自动表示失败，也不能通过全局删编号或缩小范围把结果压成一致。交付应说明原文保全范围与这些授权变化，不声称全部文字零改。
- 原稿为 PDF、图像或经过 .doc 转换时，还需核对转录/转换本身；原稿和结果的提取文字相同不能补偿共同遗漏。
- 脚本不验证字体、行距、页码准确性、分页、字段刷新和视觉质量。最终说明分别列出文本比较结果、对象复核情况和页面检查状态。
- 行距结构值及 line/lineRule 类型与实际显示需分别按本次有效规则核对，默认值见 [默认预设](default-format.md)。比较脚本不会发现固定行高裁图、keepNext 连锁导致的大空白或图片拉伸/模糊，图文接排、图题归属和引用仍须视觉检查。
- 文本一致不证明样式语义或中英数字字体符合要求。另按本次有效规则检查实际段落样式名、大纲级别、对齐、缩进、字体及其继承和直接覆盖，尤其标题/题注/公式编号、页码与刷新后的字段结果。默认值以 [默认预设](default-format.md) 为准，不在验收时反向覆盖规范。
- 当前直接 DOCX 提取支持常见 Transitional OOXML；Strict OOXML 会报输入错误，不自动转换。DOCX 中 run 的格式拆分、页/栏分隔及完全空的布局段落不作为文字改动，普通空格、Tab、软换行与表格边界仍参与比较；--loose 不取消这些结构边界。

## 最小使用判断

普通纯文本原稿可先比较文字，再检查 DOCX 实际布局；包含表格、公式或图片的 DOCX 应直接比较 DOCX，并核对工具的复核提示。合成示例只验证对应场景，不能据此承诺任意复杂模板都无损。

## 渲染工具的选择

优先采用目标环境实际提供的 Documents 技能运行时与渲染器；运行时包含 Python 不等于同时包含 LibreOffice。先确认可用能力，不硬编码解释器或转换器的本机路径。

Windows 环境中，若标准渲染器缺少依赖且 Microsoft Word 可用，可按需检查并使用 [render_word.ps1](../scripts/render_word.ps1) 只读导出 PDF：

    <powershell> -File scripts/render_word.ps1 -InputDocx <原稿或最终稿绝对路径> -OutputPdf <不存在的PDF绝对路径>

此脚本依赖本机可用的 Word 自动化能力，不是跨平台转换器；它隐藏独立实例、禁用宏、不加入最近文件、不保存源 DOCX，并拒绝覆盖已有 PDF。权限或 Word 自动化不可用时说明具体限制，不声称脚本必可运行。成功导出 PDF 后，还需用环境已有的 PDF→PNG 工具渲染并逐页查看；PDF 文件存在不能独立算作视觉验收通过。

只读导出不负责把刷新后的 SEQ、REF、目录等字段结果保存回 DOCX；如本次需要更新，按工作流单独处理并核对保存后的文件。不要为刷新排版字段而无差别刷新外部数据字段。
