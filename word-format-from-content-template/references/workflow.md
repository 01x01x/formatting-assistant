# 排版工作流

用于将现有原稿按已确定的依据制作成 DOCX。操作顺序围绕“先明确规则与保护内容，再排版和验收”，不要求为简单任务创建额外流程文件。

## 1. 确定输入与规则

先检查用户指定的文件与上下文，区分原稿、规范、模板。一个文件可以同时承担多种角色。原稿必需，排版依据也可采用已确认的 [用户默认预设](default-format.md)，模板可选：

| 已有材料 | 处理方式 |
| --- | --- |
| 原稿 + 规范或明确文字要求 | 按要求输出新的 DOCX；已有 DOCX 在副本上局部修改，不追问可选模板。 |
| 原稿 + 模板 | 继承可观察的格式；不把模板中的偶然版式推断成未提供的正式标准。 |
| 原稿 + 规范 + 模板 | 按规范调整模板，保留不冲突的有效结构。 |
| 只有原稿，或部分属性没有外部要求 | 按用户默认预设补足空缺；不因缺少可选规范或模板而停止。 |
| 缺原稿 | 先检查是否已在附件或消息中提供，再询问必要缺项；不编造稿件。 |

同一属性采用“本次明确要求 > 适用明确规范 > 模板 > 用户默认预设 > 工具默认”。例如学校规范规定不同字号时按该规范处理，不强套默认字号。规范版本不明、同一适用规范自相矛盾，或某要求会改变用户未授权修改的内容时，将具体冲突集中说明并询问；继续处理不依赖该答案的部分。补中性图表题注与必要正文引用句、公式机械独立展示与编号、默认四级标题前缀等属于已确认预设，不逐项请求批准。

完整阅读实际采用的规范；扫描图中的格式要求需要结合图像核对，不能把未识别文字当作不存在。只依据模板时，检查其样式、直接格式、节、页眉页脚和可见示例，明确观察到的规则。

把适用规则整理成简洁清单，标明来源及冲突处理结果，覆盖本次涉及的页面、字体、段落、标题、编号、页眉页脚、目录、表格等。未出现的结构不为凑齐清单而新增。封面等必填信息优先从原稿或已确认信息取得；缺少且影响成稿时再问，不将模板示例值当作用户事实。

锁定本次基底与输出文件：明确指定的路径优先；同一文件的连续修订可沿用会话中最新且已验收的当前稿，不任意切回早期原稿而丢失已确认改动。材料确实有多个无法判定的同名版本时才询问。保留原件及基底标识；派生变化相对于本次基底记录，必要时结合此前记录追溯原稿。

## 2. 盘点保护内容与模板

制作前识别原稿的正文、表格、公式、图片、文本框、脚注/尾注、批注、超链接、书签、字段、嵌入对象与修订。记录此次实际存在且需要核对的对象与关系，而非强制生成所有类型的报告。

选择能保全这些内容的基底与编辑方式：优先在副本上修改已有 DOCX；套入另一模板时保留必要的 OOXML 节点、资源与关系。不要只从 .paragraphs 或纯文本提取结果重建含对象的全文。高层库不能可靠保留某对象时，改用局部 OOXML 或目标环境可用的文档工具；仍无法保全时说明具体限制，不静默丢弃或降级对象。

原有正文论述、标题主体、表格值、公式表达式、引用及已有题注原文等是保护内容。页码、目录、中性题注、必要图表引用句、公式表示及授权编号调整另记预期变化。四级标题可按默认预设只调整已有列项的编号前缀与样式，不重写其标题文字，不把普通列表一律提升成四级标题。不要把正文中的引文编号、技术数字或普通行内数字一概视为可修改的排版内容。图表编号改变时同步相关引用；必要新增引用句仅中性描述对象，不改原有论述。已有修订、批注、书签与关联默认保留；仅在具体任务已获授权的范围内处理，不把一次删除书签的授权泛化为全局规则。

模板内容分类处理：

- **保留：**适用的学校/机构固定声明、样式、封面结构、有效页眉页脚与节设置。
- **替换或删除：**明确的姓名/题目占位内容、与原稿无关的示例正文及示例参考文献。
- **不确定：**可能是有效信息的模板文字，结合原稿与上下文判断；确实影响结果且无法判断时再问。

清理残留时搜索已识别的旧题目、旧作者、占位内容；不能仅因某词也出现在模板中便从用户原稿删除。

## 3. 选择工具与实施

目标环境提供 Documents 技能时读取并采用其运行时、依赖发现和渲染方式。否则先检查可用解释器、DOCX 库和渲染器，避免在失败后才发现工具不存在；不要求用户为普通排版任务手动安装依赖。

- .docx：用适合本次对象的文档工具或 OOXML 检查与局部编辑；python-docx 适合其能可靠处理的样式、段落、表格和节操作，不保证任意复杂对象往返无损。
- .doc：保留原件，只有在可用转换器下转为 .docx 后生产，并核对关键对象与版面。没有可靠转换能力时说明阻点，完成独立可做的规范分析，不把不可读文件当空稿。macOS 的 textutil 可辅助文字提取，不能代替格式和对象检查。
- PDF、扫描图或 Markdown 原稿：提取或转录可能丢失层级、公式和表格关系，先核对歧义；无法确定的表达不擅自改写。PDF/图像规范需要视觉核对布局示例。

在新文件或副本中显式应用有依据的样式、段落、页边距、页眉页脚、分页、节与编号设置。仅在原稿已有结构可支持时拆分或合并段落；空格涉及英文单词、代码或公式含义时不得当作纯排版噪声删除。

先设置段落实际引用的语义样式，核对继承链和有效结果，再清理与本次规则冲突的直接字体、字号、对齐或缩进；不要对全文无差别清格式。正文原有加粗、斜体、上下标、链接等有意义格式应保留；自动编号还需检查编号定义及其字体、缩进，不能只检查段落样式。标题或题注的整体格式按本次规则处理，不将文档总题目、章标题和普通列项混作同一层级。

逐一检查图表题注。已有题注保留原文字，缺失时从图表可见内容补中性简短标题；位置及编号采用本次有效规则，未被覆盖时按 [默认预设](default-format.md)，不编来源、数据结论或效果评价。审查重复、跳号、顺序、位置、SEQ 以及正文引用。只有图表主题或关联存在会影响结果的歧义时再询问。

逐一核对图表是否有正文引用；缺失时在相关位置补“如图/表×所示，……”等中性简短句，只说明可见主题或列示内容，与题注编号一一对应，不凭图表猜测效果或因果。把新增引用句纳入授权差异，不以“只排版”为由漏掉已授权新增，也不借此扩写论证。

按本次有效规则应用中文、西文与数字字体，覆盖正文、标题及其编号、表内文字、页眉页脚、目录、题注编号、公式编号、页码与字段结果；检查主题字体和直接格式的覆盖。可编辑数学文字同样按字符类型设置，不改表达；复杂符号/结构确需专用数学字体时记录具体对象、字体与原因。

实际应用本次确定的段落样式名与标题层级，复用或映射内置标题语义及相应大纲级别，正文文本保持正文语义；不能只用直接加粗/字号伪装标题。样式名、字号、加粗、对齐、缩进和行距逐属性核对；默认值只从 [默认预设](default-format.md) 读取，不覆盖适用规范。图段和高公式不套用会裁切对象的固定行高。

识别已有明确公式/算式，按需机械独立展示并优先保留或使用原生 OMML，逐项保留运算符、数值、变量、单位与解释。公式标签采用本次有效体系；默认规则的章号需来自实际结构，不能虚构章号。审查编号连续性、字段/显示结果和已有正文引用；不把普通行内数字升为公式。公式表示变化与新增标签单独记录。页码重启与页眉页脚继承按节分别检查。复杂公式、嵌入对象或引用关系的局部调整后检查其完整性，不以文本比较替代。

重复运行或追加修改前，先识别已有有效题注、引用句、公式标签和局部放大区；补缺失项或修正关联，不重复插入。图的局部放大区属于原图的组成部分，不新增独立图号。

### 渲染前检查

将相互独立的样式、题注和编号调整集中完成，首次渲染前先核对：实际段落样式/大纲级别、样式继承与直接覆盖、中西文及数字字体、行距类型、节方向、图题关联、图片纵横比、编号/引用与授权差异。优先解决可从结构确定的错误，再进入逐页视觉检查；该检查不证明图片小字清晰或页面没有留白。

## 4. 字段、目录与分页

保留用户要求的可更新字段。字段存在、刷新请求已写入、显示结果已刷新是三件不同的事；不能仅设置“打开时更新”便声称目录页码正确。

有可用刷新工具时，先更新受本次改动影响的题注/公式序号，再更新并核对对应 REF 等编号引用；完成重分页后更新目录、页码及页码引用，并检查实际显示结果。更新本身再次改变分页时复核受影响结果，不以调用成功代替稳定性检查。不要无差别刷新外部链接、导入内容或数据字段而改变原稿数据。没有刷新能力时保留有效字段并明确哪些结果尚未验证；只读 PDF 导出不等于已把更新后的字段结果保存回 DOCX。只有用户要求或已有授权允许静态目录时，才改为静态目录；静态目录页码必须基于最终分页核对。

逐页审查大面积空白，先定位不合理空段、分页/分节、keepNext 连锁和段落不可拆等限制，再适度等比调整图片并保证标注清晰。默认图片连排规则见 [默认预设](default-format.md)；不把它反向覆盖本次明确指定的版面。按默认处理时，不新增横向独占图页：图题放不下便移下一纵向页开头，让后续正文补前页，图后正文继续接排。末页自然留白与中间页异常空白分别判断，不靠缩小正文、压缩既定行距、拉伸图片或无关文字填白。移页或改尺寸后重新渲染，检查图题同页与前后页接排。

图内小字的可读性要在实际显示尺寸下先检查。原图细节完整但印刷尺寸过小时，可采用预设允许的同页局部放大；源图本身缺细节时，放大不能恢复内容，不自动重画、猜补或反复扩大。需要更清楚源图且当前材料无法解决时指出具体对象，其他部分继续处理。

## 5. 验收与停止条件

按 [质检清单](quality-checklists.md) 检查本次适用项：

1. 规则是否落实，以及哪些规则缺证据或工具支持。
2. 用户保护内容是否保留，新增题注/必要图表引用句、公式表示及授权编号调整、其他派生内容与模板固定文字的差异是否已解释。
3. 已识别的模板示例是否清理，公式、图片、注释、链接及其关系是否保全。
4. 页面是否实际渲染且全部最终页面有视觉审阅依据，实际行距、字段显示结果、图文接排及前后页大面积空白是否符合本次有效规则。

调用 scripts/compare_text.py 前读 [比较工具与验收边界](validation.md)，根据文件类型和实际比较范围解释输出。先审查完整比较中的差异，再决定是否需要排除页眉页脚等做诊断；不能靠缩小范围或忽略空白消除错误。

渲染工具可用时渲染最终 DOCX 并逐页检查，关注封面、目录、节切换、表格跨页、公式图片、参考文献及最后一页。修复发现的问题后重查受影响项目；影响分页或全局样式时重新渲染完整当前稿。若新渲染的某些页与已审阅页经像素比较确认完全相同，可沿用这些页的审阅记录，人工检查变化页及前后邻页；不凭“预计没有影响”跳过。仅有结构检查无法证明无裁切、重叠或缺字。

无法渲染时记录原因、已做的结构/内容检查及尚需核对的页面事项，交付明确标记“未完成视觉验收”的 DOCX。工具重复失败且没有新线索时停止同类重试，保留可用成果和具体限制；不把“记录了限制”勾成验收通过。

## 6. 交付

给出最终 DOCX 链接，简述采用的原稿、排版依据、模板（如有）、实际验收范围、已解释差异和未完成事项。额外格式仅按用户要求提供。无需把内部规则清单或比较报告强制作为成品附件，但应保留供定位问题；不要用“未有意改写”或单次脚本成功概括为“全文无变化”。
